- (constraint) Layer chain locked by PRD addendum: InputAdapter -> DecisionNodeFSM -> DomView; FSM publishes to EffectBus -> ParticleEngine. FX canvas never owns pointer (pointer-events: none). Hit-testing on DOM/SVG. All coords in VoidCanvas local space.
- (constraint) PRD/UX locked interaction: zone-based Solo (shard body) / Mute (rim band), no modifier keys, two mandatory channels (visual zone treatment + cursor morph); hold-to-commit 400ms with cancel on leaving shard; rim click = Eliminate, irreversible, no undo.
- (constraint) PRD/UX locked shell: single surface, no routing, no accounts, no persistence. Cold load = exactly one centered DecisionNode, 2-5 shards. Dark only, no theme toggle. Emerald tokens frozen in DESIGN.md frontmatter.
- (constraint) EffectBus capacity ~4, drop-oldest (PRD FR-9 allows 3-5). Frame budget wins over FX completeness.
- (constraint) Keyboard floor (UX EXPERIENCE.md): Tab/Shift+Tab traverse shards; Enter or Space held = Commit with same 400ms + perimeter progress; Delete/Backspace = Eliminate. Focus ring uses focus-ring token, never charge-glow. Focus is NOT a preview. Bare keys only.
- (constraint) Sensory ports required by PRD FR-8: bed-start / bed-stop-release, preview(solo|mute|neutral), eliminate-cut, commit-chord. Audio never sole signal; every audio cue has a visual twin. Bed silent until first user gesture (autoplay policy).
- (version) Verified on web 2026-07-25: vite 8.1.5 (create-vite 9.1.1, Node 20.19+/22.12+), svelte 5.56.8, @sveltejs/kit 2.70.1.
- (question) OPEN: stack choice (React / Svelte / vanilla TypeScript) - drives the DomView layer. Not yet decided by PRD or UX.
- (decision) STACK: vanilla TypeScript + Vite 8.1.5, no UI framework. Binds: all layers. Prevents: a framework reactivity model becoming a second owner of state alongside DecisionNodeFSM; also prevents React StrictMode double-invoke against the imperative ParticleEngine. Chosen over Svelte 5.56.8 and React because there is no list/form/routing/fetching surface, DESIGN.md mandates bespoke DOM/SVG with no UI system, and EXPERIENCE.md bans 'Built with React and Canvas' as the story.
- (decision) CLOCK OWNERSHIP: DecisionNodeFSM is authoritative for phase duration and input-lock windows. One generated motion module derived from DESIGN.md motion tokens is the single source of truth; CSS consumes the same values as custom properties. Clock is injected (no direct setTimeout/performance.now inside FSM) so the FSM is testable headlessly. reduced-motion is a duration profile swap, not a code branch. Prevents: CSS and FSM each owning a duration and drifting (sketch used 320ms/420ms against token totals of 520ms/580ms, so the lock opened mid-animation).
- (decision) DRAGGING PHASE DROPPED from v1. Hold-to-commit cancels when the pointer exits the shard hit region (per UX EXPERIENCE.md), not on a 6px distance threshold. The sketch's drag-out-to-eliminate (56px) and drag-overlap-to-commit verbs are NOT v1 - UX spine adopted neither and bans drag-to-reorder. Prevents: two cancel semantics (distance vs region) and an unreachable phase inviting speculative implementation.
- (event) Sketch/UX conflicts surfaced: (1) FSM setTimeout durations contradict DESIGN.md motion tokens; (2) drag verbs in sketch absent from UX spine; (3) sketch auto-promotes last surviving shard to solid, which breaks UX UJ-2 on a 3-shard node.
- (decision) ELIMINATE FLOOR AT TWO: Eliminate is refused while shard count is 2. At count 2 the rim band stops offering Mute entirely (no rim highlight, no repulse cursor, no eliminate-cut) so there is no dead click - Commit becomes the only exit. Prevents: the eliminate path silently consuming the DeferReveal hero beat, and prevents UX UJ-2 being unreachable on a 3-shard node. Replaces the sketch's finishSolid-on-last-survivor behavior. FEEDBACK OWED to UX spine (EXPERIENCE.md State Patterns has no rim-inert row).
- (decision) GEOMETRY OWNER: a pure ShardGeometry module is the single owner - deterministic function of (shard count, node radius, seam config) returning polygons, centroids, and unit outward normals, all in VoidCanvas local space. DomView renders two SVG paths per shard (body path + rim band path) from that output, so hit-testing stays DOM-native per the addendum and 'rim wins on overlap' is z-order rather than code. Prevents: DomView, HitTester, FSM, and ParticleEngine each deriving shard geometry independently.
- (decision) CHANNEL LOSS CLASS: the EffectBus is lossy by design (bounded, drop-oldest); required sensory channels - audio, cursor, DOM state - are lossless and MUST NOT be routed through the bus. AudioPort is an injected port on the FSM, sibling to the bus; the WebAudio implementation and the autoplay gate (AudioContext.resume on first user gesture) live in the adapter ring. Prevents: a builder routing commit-chord through the EffectBus where PRD FR-8's required release could be dropped under spam.
- (decision) OPERATIONAL ENVELOPE: standalone static site built with vite build, no server, no backend, no persistence, no analytics. Public entry is a framework-agnostic mountMindVoid(root, opts) returning an unmount handle; no module-level globals and no assumption that the canvas equals the viewport. Prevents: viewport-coupled sizing and global singletons that would block embedding in a portfolio shell of any framework.
- (decision) CURSOR OWNER: cursor state is DomView-owned and derived from the FSM snapshot only. The sketch had WebInputAdapter writing document.body.dataset.voidCursor directly (and independently during drag) - that is a second owner of a channel PRD FR-4/FR-5 make mandatory. Cursor is written on the mount root, not document.body, so an embedded instance cannot leak cursor state to its host.
- (decision) REDISTRIBUTING is its own phase: eliminating (eliminate-dissolve 220ms) -> redistributing (redistribute 300ms) -> hovering|idle. Two distinct motion tokens and DomView needs a distinct data-state to drive each transition; the input lock spans both. Prevents: the sketch's single 320ms gate that opened the lock while survivors were still moving.
- (decision) INTENT VOCABULARY: device-neutral intents FOCUS_SET / PREVIEW_SET / HOLD_START / HOLD_END / ELIMINATE / COMMIT / CANCEL. shardId is the ONLY field a transition may read; an optional at:{x,y} is an FX-origin hint that falls back to the ShardGeometry centroid when absent. Prevents: a parallel keyboard code path, and positional data silently affecting a transition. Replaces the sketch's POINTER_ENTER / PRESS_START / DRAG_MOVE naming and its mandatory x/y.
- (decision) SINGLE LOCK GATE: locked phases are eliminating, redistributing, committing; solid is terminal. While locked the FSM drops every intent including CANCEL. Adapters dispatch unconditionally and must not read phase; the sketch's fsm.acceptingInput check inside WebInputAdapter is removed as a second gate encoding one rule.
- (decision) TESTING: Vitest unit coverage on the pure core only (DecisionNodeFSM, ShardGeometry, EffectBus), driven by an injected fake Clock. Every transition and every input-lock window carries a test. No DOM-based or E2E testing in v1 - the headless-testability of the core is itself the case-study evidence that the FSM is platform-agnostic.
- (decision) FOCUS vs PREVIEW SPLIT: snapshot carries focusedShardId (persistent, keyboard-set) and previewShardId + previewMode (transient, pointer-set) as independent fields. Pointer never sets focus; keyboard never sets preview. Enforces UX rule 'focus is not a preview' and lets the keyboard path reuse the FSM without inheriting the Solo treatment. The sketch conflated both into focusShardId + preview.
- (decision) KEYBOARD HOLD SEMANTICS: adapter ignores event.repeat, sends HOLD_START on the first Enter/Space keydown and HOLD_END on keyup, preventDefault on Space to suppress scroll, CANCEL on blur and visibilitychange. Delete/Backspace sends ELIMINATE. Any keydown carrying a modifier is ignored (PRD bans modifier keys). ELIMINATE is refused while phase is pressing so a delete key cannot pre-empt a commit already in progress.
- (decision) FOCUS CONTINUITY: when the eliminated shard held focus, the FSM moves focusedShardId to the survivor at the same index clamped to last; it never becomes null while a shard exists. DomView keys shard elements by shard id so redistribute reuses nodes instead of recreating them, and re-applies DOM focus after redistribute completes. Prevents keyboard users being stranded mid-demo.
- (decision) COMPOSITION ROOT: mountMindVoid in app/ is the only site that constructs FSM, geometry, view, adapters, bus, particle engine, clock, audio port and motion profile. No import-time singletons. Returns an unmount handle that detaches listeners, cancels the rAF loop, clears the bus and stops audio.
- (decision) TOKEN SOURCE: DESIGN.md frontmatter is the authority for colour, motion and spacing. One generated artifact per consumer - CSS custom properties for paint, a TS MotionProfile for timing. No colour, duration or spacing literal appears anywhere else in the source. reduced-motion is a second generated MotionProfile, not overridden CSS.
- (version) Verified on web 2026-07-25: typescript 7.0.2 (shipped 2026-07-08, Go-based native compiler, no programmatic API until 7.1, bridge package @typescript/typescript6 needed by compiler-API consumers such as typescript-eslint); vitest 4.1.10 stable (5.0.0-beta.6 in beta).
- (decision) TYPESCRIPT 7.0.2 with NO typed linting. tsc --noEmit is the type-check gate; ESLint runs only rules that need no type information, so the project never depends on the programmatic compiler API that TS 7.0 dropped until 7.1 and never needs the @typescript/typescript6 bridge. Prevents: two compiler versions side by side in a demo-sized project.
- (decision) PREVIEW RE-SYNC: after leaving a locked phase (and after host resize or scroll), the pointer adapter re-hit-tests its cached last client position and dispatches a fresh PREVIEW_SET, neutral included. Adapters may observe the snapshot to detect this edge but must never gate dispatch on phase. Prevents: a stationary pointer losing its Solo/Mute preview after redistribute changes the geometry under it, which two builders would otherwise patch differently.
- (decision) HOLD CANCEL EXPRESSED AS PREVIEW: during pressing, a PREVIEW_SET naming a different shard or neutral cancels the hold and rewinds. This is how UX's 'pointer leaving the shard cancels' is expressed in the device-neutral vocabulary, with no distance threshold.
- (decision) ZONES ARE ADAPTER-LOCAL: the core knows preview MODES (solo = commit-oriented, mute = eliminate-oriented), never zones. The zone-to-mode and zone-to-intent mapping (body -> HOLD_START, rim -> ELIMINATE) lives only in the pointer adapter; the keyboard adapter maps keys to the same intents with no zone concept.
- (decision) REDUCED MOTION AS PROFILE: the reduced MotionProfile sets eliminate-dissolve 120ms, redistribute 0ms, fuse-magnetize 120ms, solid-settle 0ms. The phase graph is byte-identical; only durations differ, and a 0ms phase passes through in a single tick. Prevents a reduced-motion code branch in either the FSM or DomView.

- (decision) AD-11 TIGHTENED: bed-start fires on the first ACTIVATING intent (HOLD_START or ELIMINATE, i.e. pointerdown/keydown), never on PREVIEW_SET, because a hover grants no user activation and AudioContext.resume() would be refused; and the port re-attempts resume on every later cue instead of latching a permanent no-op. Without this the mandatory FR-8 audio channel died silently for every mouse user.
- (decision) AD-22 ADDED: ShardGeometry emits node-local polygons plus a placing transform; DomView positions one SVG group per shard by CSS transform, so redistribute is a transform transition needing no second rAF loop and no points rewrite, with an opacity cross-fade for the radial-to-binary layout family change. Every coordinate crossing a module boundary is canvas-local top-left CSS px. Closes two holes: redistribute had no legal animation mechanism, and keyboard-path FX bursts would have landed offset by the node-centre vector.
- (decision) AD-23 ADDED: fixed pointer event mapping - pointerdown on body = HOLD_START, pointerdown on RIM = ELIMINATE, no click listener anywhere, plus setPointerCapture and touch-action none. Closes a critical hole where a rim pointerdown could legally start a hold and the following ELIMINATE would then be refused in pressing, making FR-6 unreachable by pointer.
- (decision) AD-21 ADDED: Surface is a core port implemented by VoidCanvas and injected, because PointerAdapter needs the client-to-local transform and DomView needs the SVG layer, which AD-1's no-adapter-imports-an-adapter rule left with no legal answer. AD-24 ADDED: fixed emission order (snapshot subscribers, then AudioPort, then EffectBus) plus microtask-deferred re-entrant dispatch and post-unmount clock callback drop. AD-25 ADDED: shard body path is the focusable element with tabindex and an accessible name, DOM order follows shard index.
- (decision) AD-9 REWRITTEN: the EffectBus carries particle garnish ONLY - each event means 'spawn a burst here', never 'this beat happened'. Every beat is also rendered losslessly as a CSS state (dissolve, seam brighten, magnetize, cut-flash) or through the AudioPort, so a dropped bus event costs particles and nothing else. Resolves the self-contradiction where shard-commit and seam-flash carried the SM-2 hero beat over a lossy queue.
